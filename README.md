# Практика 1 / Задание 1 / Варианты 1–2

Отдельный проект C++17 для Qt Creator (Qt 5 или Qt 6, модули Core, Widgets,
3DCore, 3DRender, 3DExtras, 3DInput, Multimedia; для тестов также Test).
Рекомендуется комплект Qt 6. Все модули Qt должны быть одной совместимой версии.
Класс `Drone` разделён на `drone.h` и `drone.cpp`.

- Вариант 1: взлёт, посадка, движение, изменение заряда, вывод состояния,
  аварийная посадка.
- Вариант 2: обновление и проверка телеметрии.

Взлёт требует заряда не менее 10%, движение — не менее 5%; каждая принятая
команда взлёта или перемещения расходует 1%. Посадка и аварийная посадка снижают
БПЛА до нулевой высоты и завершают состояние полёта после касания земли.
Координаты должны быть конечными числами, высота — неотрицательной.
Конечное значение заряда ограничивается диапазоном 0–100%; NaN и бесконечность
отклоняются. Ошибочное обновление телеметрии сохраняет предыдущие данные.
Идентификатор считается корректным при `id >= 0` (0 — значение по умолчанию
из задания). Обновление телеметрии не меняет флаг полёта: им управляют методы
взлёта и посадки.

Откройте `CMakeLists.txt` в Qt Creator, выберите комплект Qt и запустите
`Practical_01_Task_1`. Откроется небольшое окно с координатами, зарядом,
кнопками взлёта, посадки, перемещения и обновления телеметрии. Текущее состояние
и результат действия отображаются в окне. Поля ввода ограничивают допустимые
значения; для проверки отказа во взлёте установите заряд ниже 10%.

Индикатор оставшегося заряда меняет цвет: зелёный при 50–100%, жёлтый при
20–49,99%, красный ниже 20%. Цвет и точный процент обновляются после взлёта,
перемещения, установки заряда и приёма телеметрии. При 0% красная рамка остаётся
видимой. При переходе ниже 20% однократно звучит `assets/lowbattery.mp3`.
Повторное предупреждение возможно после восстановления заряда до 20% или выше
и нового падения ниже порога; обновление координат не повторяет звук.

Под кнопками находится график заряда по времени: по горизонтали — секунды работы
симуляции, по вертикали — 0–100%. Он отображает последние 120 секунд. Изменения
заряда записываются сразу, на постоянном участке — раз в секунду, в том числе
на земле. Цвет линии соответствует текущему уровню заряда. `BatteryGraph`
рисуется через `QPainter`, отдельный модуль Qt Charts не требуется.

При неверном символе, выходе за диапазон, незавершённом вводе и отказе в выполнении
команды звучит `assets/critical.mp3`, а сообщение становится красным. Поле нужно
исправить перед применением: неполное число не заменяется предыдущим значением
при выполнении команды. Ошибка имеет приоритет над предупреждением о заряде.
Оба звука встроены в программу; нужен мультимедийный backend с поддержкой MP3.

Интерфейс создаётся стандартными виджетами Qt в `mainwindow.cpp`.
Консольные примеры сохранены в `demo.cpp` и запускаются целью `drone_demo`.

Справа отображается 3D-среда, адаптированная из
`Practical_03_Classes/ew_route_3d`: площадка 600 × 400 м, сетка с шагом 50 м,
цветные оси и картинка БПЛА.
Геометрия, камера и `DroneVisual` перенесены в этот проект; изображение встроено
через `assets.qrc`, поэтому исходный каталог для сборки и запуска не нужен.

Красный куб показывает координаты из полей ввода, зелёный — начало координат.
Взлёт задаёт высоту 50 м и плавно поднимает БПЛА вертикально; поле высоты также
устанавливается в 50. «Переместить» запускает плавное движение по прямой к заданным
координатам. Новая команда перемещения меняет цель из текущей позиции.
«Посадка» и «Аварийная посадка» прерывают движение и запускают вертикальное
снижение; аварийная посадка работает даже при нулевом заряде. Во время снижения
перемещение запрещено, повторное нажатие посадки не перезапускает анимацию.

Состояние и текущие координаты хранит `Drone`; метод `advance(seconds)`
продвигает движение. `QTimer` обновляет модель и сцену примерно каждые 16 мс
с учётом реально прошедшего времени. Высота в панели совпадает с текущей высотой
в сцене. Разгон и торможение сглажены функцией smoothstep. Продолжительность
взлёта/посадки рассчитывается по 25 м/с (обычный взлёт занимает 2 с), перемещения —
по 80 м/с. Это средние скорости; минимальная длительность короткого движения —
0,2 с. Кадры анимации не расходуют дополнительный заряд. Принятая телеметрия
сразу устанавливает измеренные координаты и отменяет старую анимацию.

Картинка БПЛА
поднята на 15 м над точкой координат для видимости на земле; это не меняет
показания высоты. Координаты вне площадки также допустимы.

Управление камерой: ПКМ с движением — вращение, ЛКМ — сдвиг, колесо и кнопки
«Приблизить»/«Отдалить» — масштаб. «К БПЛА» показывает текущую позицию крупнее,
в том числе вне площадки; «Общий вид» восстанавливает исходную камеру.

Из каталога этого проекта:

```sh
cmake -S . -B build
cmake --build build
./build/Practical_01_Task_1
./build/drone_demo
ctest --test-dir build --output-on-failure
```

Для сборки без тестов укажите `-DBUILD_TESTING=OFF`. Тесты проверяют модель,
плавность и прерывание движения, синхронизацию 3D-позиции с кнопками, график,
предпросмотр цели, камеру и встроенные звуки.
На Linux с рабочим столом можно сохранить снимок реального рендера:

```sh
QT_QPA_PLATFORM=xcb UAV_SCREENSHOT=/tmp/uav_sim1.png ./build/window_tests
```
